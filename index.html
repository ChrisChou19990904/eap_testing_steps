EAP 自動化工程師：規範解讀與測機標準工作流

「以 Common SPEC 與 XML 模板為基礎，確保虛實點位精準對接」

階段一：文件準備、共通規範與設定檔審查 核心：掌握 Common SPEC 與 XML 點位架構
  • Step 1
    共通通訊規範（PDF）與通訊設定檔（XML）解析
    工具：Common SPEC PDF / PLC_Pattern.xml / IO Mapping (Excel) 重點：確認雙方術語與資料型態一致
    在測機前必須徹底讀透公司標準規範文件：
    • 熟悉 Common SPEC 中的核心業務邏輯（如：Local/Remote 模式切換、歷史紀錄保留規則）。
    • 核對 PLC_Pattern.xml 中的 Event 名稱、StartAdress（如 4000 系列暫存器）與 DataType（如 short、string）。
    • 確認變數長度（DataLength）與對應的觸發旗標（Trigger Bit），避免資料寫入時發生錯位或亂碼。
  • Step 2
    離線模擬測試（PLC Simulator + HMI 虛擬對齊）
    工具：PLC 模擬器 / HMI 畫面 核心：在進廠前驗證軟體與點位邏輯
    使用模擬工具提前進行軟體沙盒測試：
    • 在模擬環境中載入 PLC_Pattern.xml，測試 EAP 是否能正確讀寫模擬暫存器。
    • 驗證各項業務功能（如：產品 MoveIn、配方下載、工單下發）的資料交換是否如預期運作。
階段二：現場實體測機與對點驗證 核心：實體心跳確認、GX Works 監控與異常防呆
  • Step 3
    實體網路層與心跳機制（Heartbeat）建立
    工具：TCP/IP 網路連線 / GX Works 監視 核心：地址 R4070 心跳判定
    機台進廠後的首要通訊驗證：
    • 確認伺服器與實體 PLC 之間的網路連線暢通。
    • 驗證心跳機制：依規範確認 PLC 定期向地址 R4070 寫入數據，EAP 接收後進行處理並回覆。
    • 透過 HMI 界面狀態（如綠色連線燈號）判定通訊正常；若心跳週期超時則直接判定為 NG。
  • Step 4
    分階段功能模組對點測試
    工具：GX Works3 線上監控 / EAP Log 追蹤 協同：帶領設備廠商逐步核對
    拿著 CheckList 與 IO Mapping 文件，與廠商逐一驗收業務模組：
    • 基礎模組：測試人員登錄、權限寫入與設備狀態讀取。
    • 核心業務：實際測試產品 MoveIn、配方請求、配方下載與 MoveOut 結案資料回傳。
    • 透過 GX Works 監控 PLC 暫存器數值變化，並對照 EAP Log 確保沒有遺漏或解析錯誤。
  • Step 5
    異常防呆與例外攔截驗證
    核心：確保程式面對壞資料不會當機
    刻意測試不符合規範的極端狀況：
    • 輸入空白字串、超長字體或錯誤的資料型態，驗證 EAP 端是否有做好 Try-Catch 與防呆攔截。
    • 確保系統在遇到異常資料時能順利記錄 Log 並跳出警報，而不會造成程式崩潰（Crash）。
